# Thermal Intelligence 1.0.0 package and verification

The 1.0.0 package is prepared and unreleased. [RC.3](rc-3.md) is the published prerelease. [Read Senyo’s community introduction](v1.0.0.md).

The rebuilt card is **268,806 bytes**, SHA-256 `2f8ac1fc486c67f409591f04532e61b05c0102ec472e599f98b32a8e0dcd7141`. Manual and Marketplace packaging each reproduced the card and licence from source `75b2d7bd939a54c7ea77401fdd75e491f94ed2b3`. The GPL licence SHA-256 is `fb981668c18a279e285fc4d83fba1e836cc84dd4daa73c9697d3cfd2d8aca6e0`.

The previous candidate was **265844 bytes**, SHA-256 `2f838e7ed3d59d4dc87f7e156872b2b820ca8cc19fa24410d66b6759190cdeba`. Version metadata and the generated banner identify `1.0.0`; the unsuffixed picker identifies the stable channel. The tested thermostat module was built from `03df08e1fbcd8c8635543bded041e2ccdf2bed8d`.

The picker name is **Thermal Intelligence Thermostat**. The rebuilt card and its exports use `custom:thermal-intelligence-thermostat`. The module also registers the beta card and editor names so saved beta/RC cards continue to work. Stable packaging requires the thermostat card and editor names for both manual and Marketplace packages. Schema-1 and schema-2 configurations remain supported.

A stable upgrade replaces the selected beta/RC resource. Do not load another module with the same registrations alongside it. Keep separate legacy Thermal Intelligence resources and cards unchanged. Retain the previous module and compatible saved configuration together for rollback. See [migration](migration.md), [configuration](card-configuration.md) and [distribution](distribution.md).

## Validation boundaries

The earlier candidate passed 203 unit, 227 synthetic browser, 14 foundation, 18 package and eight Marketplace checks. Browser coverage includes the committed stable module, beta/RC identities, legacy coexistence, configuration preservation and phone/tablet/desktop fixtures. An independent in-memory build reproduced the module exactly.

The installation, rollback and soak results below cover the earlier 265844-byte module from `03df08e`. Editor save/reload, room controls and a five-minute scheduled Boost with automatic return passed. A whole-house Boost was confirmed in seven of eight rooms. One user-locked thermostat kept its original target and the card reported Unknown after the confirmation timeout. All eight rooms returned to their starting settings. The trials verified reported requests and controls. The 48-hour Lab observation finished on 22 November 2026 with all nine checkpoints healthy. It covered Home Assistant Core, the served 1.0.0 module, the VT provider and the expected HA/VT versions. The public tagged download can be checked after release. See [compatibility](compatibility.md#unreleased-100-package).

On Home Assistant 2026.11.2, Marketplace rolled an installed 1.0.0 back to RC.4 and reinstalled the exact 1.0.0 module. Each version matched on disk, over HTTP and in a fresh browser. The existing resource ID survived both changes. Removal cleared the module and preserved the saved dashboard and unrelated resource.

The prepared stable release assets are `thermal-intelligence.js`, `LICENSE` and `manifest.json`. In a local rehearsal, Home Assistant 2026.11.2 Marketplace selected and downloaded all three from a simulated v1.0.0 release listing. Home Assistant served each file byte for byte. Separately, a fresh browser loaded the installed 1.0.0 card and editor, and the full GPL licence was available over HTTP alongside the card. The public tagged download can be checked once the release exists.

When testing an explicit development commit, a clean install could fetch the module from the default branch or pick up a historical file with the same name. The prepared layout gives the old fixture a unique filename, and the nine offline Marketplace checks cover this packaging rule. For a community install, choose the published release.

For the public 1.0.0 release, merge the pull request from `senyo888-patch-1` into `develop`, validate the candidate there, then merge the pull request from `develop` into `main`. Tag that approved `main` commit as `v1.0.0` and attach its module, licence and manifest to the release.

To rehearse packaging locally, pass the reviewed commit to the stable packager.

```sh
python3 -B scripts/package_release.py --commit REVIEWED_COMMIT --output /tmp/ti-1.0.0-manual
python3 -B scripts/package_release.py --commit REVIEWED_COMMIT --marketplace --output /tmp/ti-1.0.0-marketplace
```

The output directories must not already exist. The manifest's intended delivery branch is `main`; generating it does not promote a branch, create a tag or publish a release.
